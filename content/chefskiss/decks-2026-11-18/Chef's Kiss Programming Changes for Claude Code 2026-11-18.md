## Changes since first version (Nov 18 evening)

The first version of this file and zip went out earlier on 18 Nov. After that the Clean Kiss Crew checked the tags on their new cards and on the changed Recipes. Everything below is already applied in this version (deck `meta.version` = `pass3-crewfix-2026-11-18`). **Load the new files; don't patch the old ones.**

1. **Crew tag corrections:** 81 of the Crew's 476 new cards had wrong tags or answer types and were corrected (`ingredient_tag_changes.csv` lists every Ingredient that changed, old vs new).
2. **Food answer type:** an Ingredient now has the `food` answer type only when its subject is food. The old rule added `food` for any food word ("Juggling sandwiches at lunch", "Would Your Majesty like fries?"), so non-food cards counted as answers for flavor and snack Recipes. 150 cards in the six release decks lost `food`; 10 cards that really are food but had another subject (for example "Grandma's stinky cabbage soup") now have subject `food`.
3. **Speech answer type (Crew cards):** `speech` now needs a whole-card quote or a real speaking word. A quote mark inside the text or words like reading, letter or complaint no longer count.
4. **Six Recipe fixes from the Crew review** (Section 5.7): rc_d031, rc_d004, rc_d077, rc_m148, rc_s068, rc_s198.
5. **'event' answer-form fix:** 16 action/event Recipes had `event` in `literalTags.subject`, which penalized the very answers they ask for. It was removed (Section 5.7).
6. **New food cards and deck membership:** with honest food tags, a few flavor Recipes (rc_d031 sports drink, rc_d098 potato chip, rc_s160 birthday cake, rc_m005 ice cream) were too weak. The Crew wrote 19 new food cards (12 in deck_hot_exp1, 5 in deck_medium_base, 2 in deck_mild_exp1; IDs `ic_mfr_*`, `ic_dfr_*`, `ic_sfr_*`, `origin: "crew_food_round"`). One holdout card moved in ("A Texas-sized sandwich", Mild Expansion - 1). Each added card replaced the deck's lowest-value card, and the 20 replaced cards moved to the holdouts. Every deck is still 100 + 400. `ingredient_tag_changes.csv` lists every move.
7. **Scores changed** (Section 10). No Recipe is under 1 good answer per hand in any of the nine views.

## 3. Deck file schema (JSON)

Each `decks/*.json` file:

```json
{
  "meta": {"deckId": "deck_mild_base", "level": "mild", "name": "Mild (free starter)", "price": "free",
           "recipeCount": 100, "ingredientCount": 400, "version": "pass3-crewfix-2026-11-18"},
  "recipes": [ RecipeCard, ... ],
  "ingredients": [ IngredientCard, ... ]
}
```

Card fields follow the live `chefskiss-db.js` schema (SPEC Section 5.2), with three additions:

| Field | Type | On | Notes |
|---|---|---|---|
| `id` | string | all | Permanent. `rc_*` Recipe, `ic_*` Ingredient. |
| `type` | `"recipe"` \| `"ingredient"` | all | |
| `text` | string | all | Final wording. |
| `source` | `"official"` | all | |
| `level` | `"mild"` \| `"medium"` \| `"hot"` | all | |
| `status` | `"active"` | all | |
| `audience` | `{readingLevel, cultureLevel, knownness}` | all | Same shape as live; level copied in, knownness 4. |
| `culture` | `{born, peak, stale}` | all | All null. |
| `freshness` | number | all | 1. |
| `tags` | `{subject, tone, scale, register, violation, status}` (string arrays) | all | Six-axis tags. |
| `funnyTargetCombos` | object[] | recipe | Partial tag objects; a card scores by overlap with its best combo. **Updated** for the Recipes in Section 5. |
| `funnyTargets` | object | recipe | Union of the combos (kept for compatibility). |
| `literalTags` | object | recipe | Tags that make a plain, literal (unfunny) fit. All six axes present (empty arrays allowed). |
| `literalFor` | string[] | ingredient | Empty. |
| `aaCategory` | string | ingredient | people / things / places / events / nature. |
| `deckIds` | string[] | all | **New values**: `deck_<level>_base`, `deck_<level>_exp1`, or `deck_<level>_holdout`. Replaces `deck_official_core` for these cards. |
| `stats` | `{timesDealt, timesPlayed, kisses}` | all | Zeros. |
| `createdAt` / `updatedAt` / `version` | | all | 2026-11-18, version 1. |
| `answerTypes` | string[] | all | **New, optional for the engine.** Answer form: `thinglike`, `action`, `event`, `food`, `speech`, `sound`, or `any` (Recipes). Used by the scorer to decide if a dealt card is a real answer. See Sections 5.8 and 6.1. |
| `origin` | `"original"` \| `"crew_round1"` \| `"crew_round2"` \| `"crew_food_round"` | all | **New, info only.** Where the card came from. |
| `writtenForRecipe` | string | ingredient (Crew cards) | **New, info only.** The Recipe the Crew wrote it for. |

CSV columns (`csv/*.csv`): `card_id, type, text, subject, answer_type, source, crew_fix, reason`. Holdout CSVs also have `type = recipe_text_only` rows for the 8 retired Recipe wordings. The CSVs are for humans; the JSON is the source of truth for loading.

### 5.6 Optional engine improvement
The dealer ranks by `funnyScore` (tags only). ### 6.1 How the scorer models a hand
For a Recipe and a pool of Ingredients, every card gets `funnyScore = 2 * max(overlap(card.tags, combo) for combo in funnyTargetCombos) - 1.5 * overlap(card.tags, literalTags)`, where `overlap` weights axes subject 1.0, tone 1.5, scale 1.0, register 1.0, violation 1.0, status 1.0. The 4 matched cards come from the top `T = max(12, ceil(pool/4))` cards by score (ties shared fairly). `score_decks.py` contains the exact code.
